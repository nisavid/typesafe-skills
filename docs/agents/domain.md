# Domain documentation

Use a single context: `GLOSSARY.md` at the repository root and decisions under `docs/adr/`.

Before exploring, read the glossary and relevant ADRs when present. If they are absent, proceed without creating placeholders. Use `domain-modeling` to create them when terminology or a consequential decision is settled.

Use the glossary's terms consistently. If the current work conflicts with an ADR, identify the conflict and resolve it before changing the documented decision.
